no momento que eu reconstruir a imagem ela usou o cache da construção e a unica mudança foi no ultimo COPY
 => CACHED [2/6] WORKDIR app/                                                                                                                                                          0.0s
 => CACHED [3/6] RUN python -m venv app/venv                                                                                                                                           0.0s
 => CACHED [4/6] COPY requirements.txt .                                                                                                                                               0.0s
 => CACHED [5/6] RUN pip install --no-cache -r requirements.txt
A mudança:
 => [6/6] COPY . .

As mudanças são em cascatas, se houvesse alguma mudança nas camadas superiores todas que vem posterior a ela sofreria mudança.

Por isso, uma boa organização normalmente coloca primeiro aquilo que muda com menor frequência e depois aquilo que muda constantemente.
Dependências
     ↓
Instalação
     ↓
Código da aplicação


O que invalida o cache?
Uma etapa pode deixar de ser reutilizável quando alguma informação relevante para aquela etapa muda. Um exemplo simples é justamente o COPY.
Se temos:
- COPY requirements.txt .
e modificamos o conteúdo de requirements.txt, o Docker percebe que aquela etapa não representa mais o mesmo estado que havia sido construído anteriormente.
Portanto, ela precisa ser reconstruída.
E isso gera uma consequência importante: quando uma etapa precisa ser reconstruída, as etapas posteriores também podem precisar ser reconstruídas.

                         Sim

            Slim                     Alpine

      Menos surpresas            Mais diferenças

Para uma aplicação Python comum, python:3.13-slim é frequentemente um excelente ponto de partida.


Multi Stage
 um recurso nativo do Docker que permite organizar o processo de construção da imagem em várias etapas, isolando fases como compilação, testes e empacotamento.

Stage 1
builder
    │
    │ compila
    ▼
   app
    │
    │ COPY --from=builder
    ▼
Stage 2
runtime
    │
    ▼
aplicação executando

Um artefato é simplesmente o resultado produzido durante o processo de construção que será utilizado posteriormente.
A imagem final não precisa carregar o código-fonte, o compilador e todas as ferramentas utilizadas para gerar o binário.

CONSTRUÇÃO
                    │
                    ▼
          "Como produzo minha aplicação?"
                    │
                    ▼
        compiladores / ferramentas /
          dependências de build
                    │
                    ▼
                 ARTEFATO
                    │
                    ▼
                 EXECUÇÃO
                    │
                    ▼
          "O que preciso para rodá-la?"
                    │
                    ▼
             runtime + aplicação

Imagine uma fábrica de móveis.
Você precisa de:
- serra
- furadeira
- martelo
- máquinas
- matéria-prima

para fabricar uma mesa.
Mas quando a mesa está pronta, você não precisa colocar:
- serra
- furadeira
- martelo
dentro da casa do cliente.
Você entrega: mesa

A fábrica é o builder.
A mesa é o artefato.


Aqui existe uma conexão importante com o que você estudou anteriormente.
Você já aprendeu que uma imagem é formada por camadas.
Com Multi-stage, existem múltiplas etapas de construção, mas a imagem final não precisa carregar todas as camadas produzidas pelo estágio de build.
